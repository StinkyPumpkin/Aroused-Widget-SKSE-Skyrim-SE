# Building ArousedWidget

ArousedWidget 3.8.0+ builds against **CommonLibSSE-NG 9.1.0** from alandtse
(`https://github.com/alandtse/CommonLibSSE-NG`, formerly `alandtse/CommonLibVR`, branch `ng`),
compiled from source out of the git submodule `extern/CommonLibSSE-NG`, pinned to tag
**`v9.1.0` = commit `a898f469851c464d05137bb74b069dd234897643`**.

One DLL covers Skyrim SE 1.5.97, AE 1.6.x (including 1.6.1170), AE 1.7.x (1.7.99 / 1.7.104) and VR 1.4.15.
NG 9.1.0 is the first line that has everything 1.7 needs together:

| NG version | What it added |
|---|---|
| 6.4.0 | reads the Address Library v5 database (format 5, 1.7.x `versionlib-1-7-*.bin`) |
| 6.5.0 - 6.6.3 | 1.7.99 layout changes (SkyrimVM, PlayerCharacter, State, MapMenu) |
| 6.7.0 | `kVersionIndependentEx_AddressLibraryV5` flag defined |
| 7.5.3 | PlayerCharacter 1.7.x accessors corrected |
| 8.0.1 | the V5 flag is **set by default** in every plugin declaration (1.7 SKSE skips a DLL without it) |

Up to 0.4.0 the widget used `commonlibsse-ng` 3.7.0 from the Monitor221hz vcpkg registry, which stops at 1.6.678
and has no V5 flag, so 1.7 SKSE skipped the DLL. (The version jumped from 0.4.0 to 3.8.0 to follow the Nexus page.)

## Toolchain

- Visual Studio 2022 Community, MSVC **14.44** (`cl` 19.44). The overlay triplet `cmake/x64-windows-static.cmake`
  pins the vcpkg dependencies to the same 14.44 toolset.
- CMake 3.21+ and Ninja (both ship with VS 2022).
- vcpkg at `C:\vcpkg` (`VCPKG_ROOT`), manifest mode. Registry = microsoft/vcpkg only, baseline
  `ee12231b20c95013c6638d845d04c91559a1d1ff` (the same baseline NG 9.1.0 builds with): fmt 12.1.0,
  spdlog 1.16.0, directxtk 2025-10-27, directxmath 2025-04-03, rapidcsv 8.90.
- Static CRT (`x64-windows-static`, `/MT`).

## Steps

```bat
git clone https://github.com/StinkyPumpkin/Aroused-Widget-SKSE-Skyrim-SE.git
cd Aroused-Widget-SKSE-Skyrim-SE
git submodule update --init --recursive --depth 1
build.bat
```

`--recursive` also fetches NG's own `extern/openvr` submodule (VR is enabled, so NG links `openvr_api.lib`).

`build.bat` runs `vcvarsall.bat amd64` (VS 2022 Community), sets `VCPKG_ROOT=C:\vcpkg`, configures
`build\ng\release` with `cmake --preset release` on first run, then `cmake --build build\ng\release`.
Output: `build\ng\release\ArousedWidget.dll`. A first build compiles CommonLibSSE-NG itself (about 500 files).

If `SKYRIM_MODS_FOLDER` is set, POST_BUILD copies `ArousedWidget.dll` into
`%SKYRIM_MODS_FOLDER%\Aroused Widget--Claude\SKSE\Plugins`. Don't build while the game is running. The build never
copies or writes `config.json`: the widget creates it on first save (MO2: overwrite).

## CommonLib options (set in CMakeLists.txt before `add_subdirectory`)

| Option | Value | Why |
|---|---|---|
| `ENABLE_SKYRIM_SE` / `_AE` / `_VR` | ON / ON / ON | same runtime set as 0.4.0; AE covers 1.6.x and 1.7.x |
| `BUILD_TESTS` | OFF | NG defaults ON, which needs Catch2 |
| `SKSE_SUPPORT_XBYAK` | OFF | the widget uses no trampoline |
| `SKSE_SUPPORT_PATCH_SAFETY` | OFF | only checks `write_branch` sites (the widget has no hooks); ON downloads minhook at configure time |
| `REX_OPTION_INI/JSON/TOML` | OFF | unused |

NG's source build does not define `add_commonlibsse_plugin()`; CMakeLists includes
`extern/CommonLibSSE-NG/cmake/CommonLibSSE.cmake` for it. `MINIMUM_SKSE_VERSION 0.0.0` must be a full triplet
(the helper's bare `0` default generates code that doesn't compile).

## Plugin declaration

Generated by `add_commonlibsse_plugin`: exports `SKSEPlugin_Version` (read by AE/1.7 SKSE), `SKSEPlugin_Query`
(SE/VR SKSE) and `SKSEPlugin_Load`.

- `versionIndependence` = `AddressLibraryPostAE` (Address Library independent, no fixed runtime list)
- `versionIndependenceEx` = `AddressLibraryV5 | NoStructUse` (0x3)

## Notes for the NG 9 code

- `SKSE::Init(skse, { .log = false })`: NG 9's Init opens its own `<plugin>.log` by default and would replace the
  widget's logger. The load log carries `built on CommonLibSSE-NG <version>`.
- With VR enabled NG declares members whose layout differs per runtime behind accessors. The widget reads
  `PlayerCamera::cameraStates` through `GetRuntimeData()` / `GetVRRuntimeData()`, and `CrosshairPickData`'s
  target actor through `REL::RelocateMember` (0x08 SE/AE, 0x10 VR).
- The widget installs no hooks and no vtable patches: input arrives through SKSE Menu Framework's
  `AddInputEvent`, so the 1.7.99 input-handler vtable shift (ProcessButton slot 4 -> 6) does not apply.

## Updating NG

```bat
cd extern\CommonLibSSE-NG
git fetch --tags --depth 1 origin tag vX.Y.Z
git checkout vX.Y.Z
git submodule update --init --recursive --depth 1
cd ..\..
rmdir /s /q build\ng
build.bat
```

Then commit the submodule pointer. Read NG's CHANGELOG for breaking changes first. NG 9.x is
GPL-3.0-or-later; ArousedWidget is GPL-3.0.
